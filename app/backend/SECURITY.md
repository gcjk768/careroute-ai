# CareRoute AI Backend — AI Security Risk Register

Concise risk register mapping the backend's threat surface to the
[OWASP Top 10 for LLM Applications](https://owasp.org/www-project-top-10-for-large-language-model-applications/)
and the concrete control implemented in this codebase for each risk.
File paths are relative to `app/backend/`.

**Numbering: OWASP LLM Top 10 for 2025**, the edition taught in AIC Day 2 and used by
the `Workshop-2/Solutions/LLM-01..10` handouts:

| | | | |
|---|---|---|---|
| LLM01 Prompt Injection | LLM02 Sensitive Information Disclosure | LLM03 Supply Chain | LLM04 Data and Model Poisoning |
| LLM05 Improper Output Handling | LLM06 Excessive Agency | LLM07 System Prompt Leakage | LLM08 Vector and Embedding Weaknesses |
| LLM09 Misinformation | LLM10 Unbounded Consumption | | |

This matters because the 2023 edition numbered the same risks differently — *Excessive
Agency* was LLM08 and is now LLM06, *Insecure Output Handling* was LLM02 and is now LLM05,
*Overreliance* was LLM09 and is now *Misinformation*. An earlier version of this table mixed
both editions, which made two rows claim LLM02 for different risks.

| Risk | OWASP LLM Top 10 (2025) | Concrete control in this codebase | Where |
|---|---|---|---|
| Prompt injection / jailbreak input attempts to hijack agent behaviour or exfiltrate the system prompt | **LLM01** Prompt Injection | Deterministic, regex-based guardrail screen runs **before** any agent sees the input; blocks known injection/jailbreak phrasings, and never depends on an LLM being reachable (it cannot itself be prompt-injected) | `app/guardrail.py` (`screen()`), invoked first in `_triage_event_stream()` in `app/main.py` |
| A malicious/compromised model response contains instructions, code, or malformed structure that gets executed or trusted downstream | **LLM05** Improper Output Handling | Every LLM call requests `format: json` and STRICT-JSON instructions; the response is defensively parsed (`_extract_json`), and any field used downstream is type/whitelist-validated (e.g. `acuity_code` must be one of 5 known enum values, `confidence` clamped to `[0,1]`) before being trusted. Any parse/validation failure raises and triggers the deterministic fallback — the raw model text is never `eval`'d, rendered, or passed to a shell | `app/llm.py` (`_extract_json`, `complete`), `app/agents/classifier.py` (`SeverityClassifierAgent.run`), `app/agents/intake.py` (`SymptomIntakeAgent.run`) |
| The classifier silently produces a dangerously wrong (too-low) acuity and nothing catches it | **LLM09** Misinformation | A wholly separate, deterministic Safety-Override worker re-screens raw text against a hard-coded red-flag rule table; it can only ever **raise** acuity severity, never lower it (`apply_override`/`more_severe`), so it acts as an un-overridable safety net regardless of classifier/LLM output | `app/redflags.py`, `app/agents/safety.py` (`SafetyOverrideAgent`) |
| An agent uses a tool/capability outside what it actually needs (e.g. the intake agent creating escalations, or the router calling the LLM) — excess blast radius if any single agent is compromised or buggy | **LLM06** Excessive Agency | Every worker declares an explicit `TOOL_ALLOWLIST` + `AUTONOMY_LEVEL` (Spectrum of Agency L1–L3); `enforce_tool_access(agent, tool)` is called at the actual tool-use call sites (classifier's `rag.retrieve`, routing's `clinic.lookup`, safety's `redflags.evaluate`, and the escalation-creation call in `main.py`) and raises `ToolAccessError` if a tool isn't in the caller's allow-list — least privilege is enforced at runtime, not just documented | `app/agents/base.py` (`enforce_tool_access`, `ToolAccessError`) with a per-agent `TOOL_ALLOWLIST` in each `app/agents/<agent>.py`; `app/main.py` (`enforce_tool_access(...)` for `"escalation.create"`) |
| Low-confidence or genuinely ambiguous model output is acted on autonomously with no human check | **LLM06** Excessive Agency / **LLM09** Misinformation | Human-in-the-Loop worker deterministically escalates whenever classifier confidence falls below `CONFIDENCE_THRESHOLD` (0.5, calibrated) **or** a safety-override fired — mandatory HITL gate, not optional | `app/agents/hitl.py` (`HumanInTheLoopAgent`, `CONFIDENCE_THRESHOLD`) |
| Patient free-text (potentially containing PII/PHI) is logged, cached, or leaked via prompts/telemetry | **LLM02** Sensitive Information Disclosure | No secrets are ever embedded in prompts (system prompts are static clinical-role text); no external telemetry; **prompt/response content is never written to logs** — only provider names and outcomes are logged. **Trust-boundary note:** the provider (OpenAI) sends patient text to a cloud LLM. For a real-PHI deployment, point `OPENAI_BASE_URL` at a BAA-covered endpoint, or keep the deterministic fallback. This is a deliberate, configurable trade-off, documented in `.env.example` | `app/llm.py`, `app/config.py`, `.env.example` |
| Provider secrets (`OPENAI_API_KEY`) hard-coded, committed, or leaked via logs/errors | **LLM02** Sensitive Information Disclosure / secrets hygiene | Secrets are read from the environment only (`app/config.py`), never hard-coded and never logged; `.env` is gitignored and `.env.example` ships blank. The local-tool providers (a developer CLI, Ollama) were removed so no developer credential can ever answer production traffic | `app/config.py`, `app/llm.py`, `.env.example`, `.gitignore` |
| Full agent reasoning/decisions are opaque, so a wrong or unsafe outcome can't be audited or reproduced after the fact | **LLM09** Misinformation / traceability (FR-13) | Every pipeline step (guardrail, each of the 5 workers, final aggregation) is written to an ordered, per-case `AuditLog` (actor, action, detail, confidence, acuity) plus structured `logging` output, and is retrievable via `GET /api/cases/{case_id}/audit` | `app/audit.py`, `app/main.py` (`audit_log.record(...)` calls, `get_case_audit`) |
| Unbounded/oversized input used for resource-exhaustion (DoS) or to smuggle large payloads past screening | **LLM10** Unbounded Consumption (oversized input) | Guardrail rejects empty input and input over 6000 characters before any agent or LLM call is made; **every provider enforces its own timeout** (OpenAI 30s read) so a hung provider can't stall a request — and on timeout the chain moves to the next provider, then to deterministic logic | `app/guardrail.py` (`screen`), `app/llm.py` (per-provider timeouts), `app/config.py` |
| A compromised/unavailable local model is silently trusted, producing a plausible-looking but ungrounded diagnosis | **LLM09** Misinformation | Every LLM-backed worker has a fully deterministic, rule-based fallback (keyword rules for intake/classification) that activates on ANY LLM failure (timeout, connection error, invalid JSON, invalid enum value) — the system degrades to a known-safe deterministic mode rather than failing open or hallucinating | `app/agents/intake.py` (`SymptomIntakeAgent._fallback`), `app/agents/classifier.py` (`SeverityClassifierAgent._fallback`), `app/llm.py` (`LLMUnavailableError`) |
| Citations/evidence presented to a clinician are fabricated by the model rather than grounded in real guidance | **LLM09** Misinformation (ungrounded generation) | Citations come from a fixed, hand-authored clinical-guidance corpus retrieved via **TF-IDF vector-similarity** (`rag.retrieve`), not generated free-text from the LLM, and access to it is itself gated by the classifier's least-privilege allow-list | `app/rag.py`, `app/agents/classifier.py` (`_gather_supporting_evidence`) |
| A model that a novel/multi-turn attack coaxed into leaking its system prompt or emitting injected instructions surfaces that text verbatim to a clinician | **LLM07** System Prompt Leakage / **LLM05** Improper Output Handling | An **output-side** guardrail screens the (LLM-influenced) rationale before the final event; on a prompt-leak/injection match it suppresses the text (safe fallback) and audits the event — "never trust LLM output blindly" | `app/guardrail.py` (`screen_output()`), `app/main.py` (before the `final` SSE event) |
| Direct patient identifiers (NRIC/FIN, phone, email, MRN) reach a cloud LLM or persistent storage | **LLM02** Sensitive Information Disclosure | Deterministic redaction masks structured identifiers **before** the text is sent to any provider or written to the store; clinical symptom words are preserved so triage is unaffected; masked kinds are audited (Presidio is the prod drop-in) | `app/redact.py`, `app/main.py` (`redact.redact(req.text)`), and the same masking is applied to patient feedback comments and clinician decision notes before they are stored (`main.submit_feedback`, `store.decide_escalation`) |
| Request flooding exhausts the LLM/ML path or runs up cost | **LLM10** Unbounded Consumption | Per-client fixed-window rate limiter rejects over-limit callers with 429 **before** any expensive work; keyed on client IP (proxy-aware) with a session fallback | `app/ratelimit.py`, `app/main.py` (`rate_limiter.allow(...)`) |
| A compromised/looping agent keeps acting autonomously and its decision log can be quietly altered | **ASI10** Rogue Agents | A **kill switch** (`CAREROUTE_KILL_SWITCH`) forces the whole pipeline onto deterministic, auditable rules (revokes LLM autonomy); the per-case audit log is **SHA-256 hash-chained**, so any altered/removed entry is detectable via `verify_chain` (surfaced as `verified` on `GET /api/cases/{id}/audit`) | `app/config.py`, `app/llm.py` (kill switch), `app/audit.py` (`_entry_hash`, `verify_chain`) |
| A dependency, base image, model file or third-party tool ships tampered or vulnerable code into the build | **LLM03** Supply Chain | Pinned dependencies + a CycloneDX **SBOM** per build; Trivy blocks CRITICAL CVEs, with OSV/Grype/Dependency-Check/Retire.js advisory; **modelscan** and **fickling** scan the serialized model for deserialisation payloads — the attack path a `.joblib` actually has | `.gitlab-ci.yml` (`scan:sbom-cyclonedx`, `scan:trivy-fs`, `scan:deps-*`, `scan:modelscan`, `scan:model-fickling`) |
| Poisoned training data silently suppresses red-flag detection before the model is ever served | **LLM04** Data and Model Poisoning | The **release gate** blocks persistence and registration below 0.95 red-flag recall, and `test_ml_attacks.py` proves it: a 10% red-flag→P5 label flip drops recall to ~0.915 and the gate rejects it. Dataset provenance is content-addressed (`dataSha256`) and re-derived by `data:version --check`, so an undeclared data change fails the build | `app/ml/train.py` (`validate`), `app/ml/model.py` (`MIN_RED_FLAG_RECALL`), `tests/test_ml_attacks.py`, `data:version` |
| The retrieval corpus is poisoned or an embedding-similarity collision returns attacker-chosen "guidance" | **LLM08** Vector and Embedding Weaknesses | The corpus is **hand-authored, git-committed and read-only at runtime** — there is no user-writable ingestion path, which removes the usual injection route. Retrieval is **lexical TF-IDF** over that fixed corpus (no embedding model or vector store), and citations carry their source id so a clinician can check the claim against the text. The optional Onyx backend IS an external ingestion path: its hits are NFKC-sanitised, length-capped and screened with the LLM05 output guard, and a flagged hit is dropped and counted (`careroute_untrusted_content_drops_total`) — `tests/test_rag_injection.py` | `app/rag.py`, `app/guardrail.py` |
| An adversary perturbs the input feature vector to force a mis-triage (evade a P1 into a P5) | Classical **evasion** (AIC Day 1) | Real IBM ART **HopSkipJump** black-box attack in CI asserts a robustness floor: the forest must survive in-budget (L-inf ≤ 0.25) perturbations | `tests/test_robustness.py`, `test:robustness` |
| Query access to `/api/triage` reveals whether a given patient record was in the training set | Classical **privacy: membership inference** (AIC Day 1) | ART `MembershipInferenceBlackBox` gated in CI at ≤ 0.60 attack accuracy (chance = 0.50); measured ≈ 0.55 on the deployed forest | `tests/test_ml_attacks.py`, `ai-security:ml-attacks` |
| Repeated queries let an attacker clone the model (**accepted risk, not mitigated**) | Classical **privacy: model extraction** (AIC Day 1) | **Measured: ~500 queries reproduce 96% of the model's decisions, ~2000 reproduce 100%.** A 200-tree forest over 22 features is cheap to clone and no defence here changes that. What the rate limiter (30 req/min/client) buys is *time and noise* — 2000 queries is >1 hour from one key — not prevention. Accepted because the model is not the asset: it is trained on synthetic data, its logic is published in `MODEL_CARD.md`, and a clone confers no access to patients. **Reproduce the curve:** `python -m app.ml.extraction` (surrogate forest trained on label-only answers, scored on unseen rows); pinned by `test_model_extraction_probe_reproduces_the_documented_curve` | `app/ml/extraction.py`, `tests/test_ml_attacks.py`, `app/ratelimit.py`, `backend/MODEL_CARD.md` |

## Agentic threats — OWASP Agentic AI Top 10 (ASI01–ASI10)

AIC Day 3 and the OWASP *Agentic AI Threats and Mitigations* guide (T1–T17) both argue that an
agentic system inherits every LLM risk above and adds new ones from **tool use, memory,
identity and inter-agent protocol**. CareRoute is a supervisor over six workers, so the taxonomy
applies — but much of it applies by *not being reachable*, and saying so is more useful than
claiming a control that does not exist.

| OWASP | Threat | CareRoute position |
|---|---|---|
| **ASI01** | Agent Goal Hijack | Guardrail screens input before any agent runs; every LLM system prompt carries the shared `EMBEDDED_INSTRUCTION_GUARD` (patient text AND retrieved/remembered documents are data, never instructions), asserted by `tests/agents/test_prompt_hygiene.py`; retrieved Onyx hits and the recalled prior-visit summary are sanitised and screened before they can reach a prompt (`tests/test_rag_injection.py`); goals are Python constants, not model-settable |
| **ASI02** | Tool Misuse & Exploitation | Static per-agent `TOOL_ALLOWLIST` + `enforce_tool_access()` at the call site. Since 2026-09-15 ONE agent does select tools at runtime — Care-Routing's bounded ReAct loop chooses from a two-entry registry (`travel.estimate`, `facility.hours.lookup`), at most 3 turns, arguments schema-validated, clinic ids checked against the candidate list, every call traced into `routing_plan.tool_calls` (`tests/agents/test_routing_react.py`). Every other worker's tool use is fixed Python, so there is no tool-choice to manipulate there |
| **ASI03** | Identity & Privilege Abuse | **Partial.** Workers run in-process under one identity; there are no delegation chains or cached credentials to escalate through, but equally no per-agent identity to revoke |
| **ASI04** | Agentic Supply Chain | No dynamically loaded agents, tools, prompts or MCP servers — the graph is fixed at import. Dependency/model provenance covered by LLM03 above |
| **ASI05** | Unexpected Code Execution (RCE) | No agent generates or executes code; no `eval`, no shell, no code-interpreter tool. LLM output is parsed as JSON and enum-validated before use |
| **ASI06** | Memory & Context Poisoning | `CaseState` is per-request and the RAG corpus is read-only. The cross-visit path (`store.recall_session`) is now **integrity-checked**: each case is SHA-256 fingerprinted on write (`store.memory_digest`) and re-verified on read, and a record that fails — or has no digest at all — is **excluded from recall** rather than returned with a warning. `verify_episodic_memory()` reports what was excluded, because a control that only fails quietly is indistinguishable from one that never fires |
| **ASI07** | Insecure Inter-Agent Communication | **N/A by architecture.** Workers exchange typed dicts inside one process; there is no network hop to spoof, replay or MITM. Becomes live the moment a worker moves out-of-process |
| **ASI08** | Cascading Failures | Step budget (≤ 9 turns, `test:agent-graph`), deterministic fallback, and a **circuit breaker** on the LLM provider chain (`app/llm.py`): after 3 consecutive failures a provider is skipped until a cooldown elapses, then one half-open trial decides whether it reopens. Without it a dead provider is waited on once per worker per case — five times over, its full timeout each — which is the amplification ASI08 is actually about. State is exposed on `/api/health`; Safety-Override can still only *raise* acuity, so one bad worker cannot lower it |
| **ASI09** | Human-Agent Trust Exploitation | The clinician UI shows SHAP contributions, cited sources and a confidence value rather than a bare confident answer; low confidence forces HITL escalation instead of silent action |
| **ASI10** | Rogue Agents | Kill switch + hash-chained audit log — see the table row above |

## Agentic threats — OWASP *Agentic AI Threats and Mitigations* (T1–T17)

The ASI01–ASI10 list above is the Top-10 view. The course's guide (*Agentic AI — Threats and
Mitigations* v1.1) is the fuller taxonomy, T1–T17, and several of its entries became live only
when an agent started choosing tools and control flow (Care-Routing's ReAct loop, 2026-09-15; the
Reflection critic, 2026-09-16). Each row states the control, or says **Partial** / **Gap** and why.

| # | Threat | CareRoute position | Evidence |
|---|---|---|---|
| **T1** | Memory Poisoning | Episodic memory is SHA-256 fingerprinted on write and re-verified on read; a record that fails or has no digest is excluded. Recalled prior-visit TEXT is sanitised and screened before it enters a prompt, and dropped if flagged. Session ids are shape-validated and TTL-bounded. The LLM response cache is exact-match and holds only provider answers, so there is no write path an attacker controls | `store.memory_digest`, `main._recall_prior_visit`, `tests/test_rag_injection.py`, `llm._cache_key` |
| **T2** | Tool Misuse | Two-key authorisation (tool `allowed_agents` AND caller `TOOL_ALLOWLIST`), JSON-schema argument validation before any handler runs, read-only tools only, per-loop call caps (critic 3, Care-Routing 3), every call counted by outcome | `app/tools/registry.py`, `tests/test_tool_registry.py`, E6 + E11 |
| **T3** | Privilege Compromise | **Partial.** Agent write lanes are enforced by `AgentContract` tests and tool grants by the E6 matrix, but all workers run in one process under one OS identity, and staff endpoints use a single shared API key | `tests/agents/test_contracts.py`, `tests/test_eval_tool_access.py`, `config.STAFF_API_KEY` |
| **T4** | Resource Overload | Per-client rate limit; ≤ 9 agent steps per triage; Reflection loop iteration cap + wall-clock budget; critic timeout (90 s) and tool-turn cap; Care-Routing OneMap per-case budget + circuit breaker; per-provider LLM circuit breaker; bounded LRU response cache | `ratelimit.py`, `test_agent_graph.py`, `reflection.py`, `llm.py` |
| **T5** | Cascading Hallucination Attacks | Every LLM step has a deterministic fallback; every merge is monotone (Safety-Override and the critic can only raise caution); LLM JSON is enum-validated before use; the classifier declines invalid codes instead of rescuing them; rationale and handoff text pass the output guardrail | `agents/reasoning.py`, `reflection.run`, `classifier._commit`, E11 |
| **T6** | Intent Breaking & Goal Manipulation | Input guardrail before any agent; one shared embedded-instruction guard in every system prompt (patient text and retrieved/remembered documents are data); goals and action spaces are code constants — the critic may only answer accept / escalate / rerun | `guardrail.py`, `tests/agents/test_prompt_hygiene.py`, `reflection.CRITIC_ACTIONS` |
| **T7** | Misaligned & Deceptive Behaviors | The deterministic red-flag table cannot be overridden by any model; model output that tries to lower acuity or de-escalate is ignored by construction and tested adversarially (E11: 0 violations); explanation provenance is labelled so an LLM self-report is never shown as SHAP | `redflags.py`, `tests/agents/test_reflection_critic.py`, `CaseState.explanation_source` |
| **T8** | Repudiation & Untraceability | **Partial.** Every step, tool call trace and clinician decision is written to a SHA-256 hash-chained, per-case audit log, and decisions carry the signed-in clinician's name. The log is in-memory, so it does not survive a restart, and the staff name is self-asserted by the mock login | `audit.py`, `ClinicianDashboard.jsx`, `store._record_ground_truth` |
| **T9** | Identity Spoofing & Impersonation | **Partial.** Agent identity on the A2A bus is checked (`enforce_comms`; Reflection's attribution check flags an unannounced routing decision). Human identity is not strong: one shared staff key and a front-end-only login | `agents/messaging.py`, `reflection.verify_announcements`, `frontend/lib/auth.js` |
| **T10** | Overwhelming Human-in-the-Loop | **Partial.** The HITL trigger is gated on specificity as well as recall (E5), so escalating everything cannot pass. The LLM critic can add escalations and there is no gate yet on its escalation rate; `careroute_escalations_total` makes the volume observable | `app/evals/plan.E5_HITL_TRIGGER`, `metrics.ESCALATIONS` |
| **T11** | Unexpected RCE and Code Attacks | No agent generates or executes code; no shell or interpreter tool exists in the registry; LLM output is parsed as JSON and validated, never evaluated | `app/tools/registry.py` (catalogue), ASI05 above |
| **T12** | Agent Communication Poisoning | Typed `AgentMessage` bus with least-privilege publish/subscribe per agent (`COMMS`), recorded in the audit trail; no raw patient text on the bus | `agents/messaging.py`, `tests/agents/test_comms.py` |
| **T13** | Rogue Agents in Multi-Agent Systems | Kill switch forces deterministic-only mode; each reasoning layer (semantic safety, critic) is individually switchable; the capability audit fails the build if an agent's declared classification, tools or model use drift from its code | `CAREROUTE_KILL_SWITCH`, `CAREROUTE_LLM_CRITIC`, `tests/agents/test_capability.py` |
| **T14** | Human Attacks on Multi-Agent Systems | The step order is fixed and safety-gated, so a user cannot steer delegation between agents; user input is screened before the first agent; the only model-chosen control flow (the critic) can only add caution | `agents/orchestration.py`, `guardrail.screen` |
| **T15** | Human Manipulation | **Partial.** The patient sees labelled evidence (SHAP source, counterfactual stated as "describes the model, not medical advice"), an AI-use disclosure and cited guidance; clinician-facing LLM text passes the output guardrail. No test measures persuasive or manipulative phrasing | `PatientTriage.jsx`, `guardrail.screen_output` |
| **T16** | Insecure Inter-Agent Protocol Abuse | In-process A2A has no network hop. The MCP server publishes only read-only registry tools over local stdio and routes every call through the gateway; it has no authentication of its own, so it must not be exposed beyond the local host | `app/mcp_server.py`, `tests/test_mcp_server.py` |
| **T17** | Supply Chain Compromise | **Partial.** Pinned dependencies, CycloneDX SBOM, Trivy, pip-audit, `modelscan` + `fickling` on the model artifact, SHA-256 sidecar on the model. Optional agentic packages are pinned to versions resolved against the existing lock. **Gap:** the embedding model is downloaded by name at first use and is not hash- or revision-pinned | CI `security-scan`, `requirements-agentic.txt`, `rag_embed.FASTEMBED_MODEL` |

## Automated scanning (CI/CD)

Beyond the controls above, the CI pipeline (`.gitlab-ci.yml` at the repo root)
runs a suite of **free / open-source** scanners across its `ai-security` and
`security-scan` stages — see `../security/README.md` for the full list and how
to run them locally:

- **LLM red-teaming:** Promptfoo (per-PR regression when an API key is present;
  advisory), Garak (manual per-release vuln scan against the vendor model — 120+
  probes), DeepTeam (manual, OWASP LLM Top 10, vendor model with a stand-in
  prompt), PyRIT (**placeholder job only** — `security/pyrit_orchestration.py`
  is not yet written),
  plus our always-green pytest guardrail regression.
- **Responsible-AI gate:** Fairlearn subgroup accuracy-parity gate
  (`tests/test_fairness_gate.py`) — fails if the model regresses to the
  age-blind baseline.
- **AppSec:** Gitleaks (secrets), Semgrep + Bandit (SAST), Trivy
  (deps/secrets/IaC/image), pip-audit + Safety / npm audit (SCA), modelscan
  (serialized-model), OWASP ZAP (DAST), Hadolint (Dockerfile).
